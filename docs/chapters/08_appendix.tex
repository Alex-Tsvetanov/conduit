\subsection*{Приложение А. Схема на тестовата база}

Схемата се създава от самата измервателна програма в началото на всеки пуск, така че
началното състояние е част от измерването, а не предположение за него. Таблицата се
пълни с 5000 реда, освен ако не е зададено друго с \code{--rows=N}.

\begin{lstlisting}[language=SQL,caption={Схема на измервателната таблица, PostgreSQL},label={lst:schema-pg}]
DROP TABLE IF EXISTS conduit_bench;
CREATE TABLE conduit_bench (
    id     bigint primary key,
    label  text,
    value  double precision,
    flag   boolean);
-- 5000 реда, вмъкнати с едно заявление:
-- (1,'label1',1.5,true), (2,'label2',3.0,false), ...
\end{lstlisting}

\begin{lstlisting}[language=SQL,caption={Схема на измервателната таблица, MySQL},label={lst:schema-my}]
DROP TABLE IF EXISTS conduit_bench;
CREATE TABLE conduit_bench (
    id     bigint primary key,
    label  varchar(64),
    value  double,
    flag   tinyint(1));
\end{lstlisting}

Показната програма и интеграционните тестове ползват втора таблица с по-широк набор от
типове, включително \code{numeric}, \code{timestamp} и масив, за да бъде проверено
декодирането на всеки от тях:

\begin{lstlisting}[language=SQL,caption={Таблица за проверка на декодирането на типовете},label={lst:schema-types}]
CREATE TABLE conduit_items (
    id      bigint primary key,
    label   text,
    weight  double precision,
    flag    boolean,
    amount  numeric(12,3),
    made_at timestamp,
    tags    int4[]);
INSERT INTO conduit_items VALUES
 (1,'alpha',1.5,true, 123456.789,'2024-02-29 13:45:30.123456','{1,2,3}'),
 (2,'beta', 2.5,false,    -0.050,'1999-12-31 23:59:59',       '{}'),
 (3,'gamma',3.5,true,      0.001,'2000-01-01 00:00:00',       NULL);
\end{lstlisting}

\lstinputlisting[language={},caption={\code{docker-compose.yml}: версиите на сървърите,
с които са направени измерванията},label={lst:compose}]{../docker-compose.yml}

Портовете са изместени от подразбиращите се, за да не се сблъскат контейнерите с
евентуално вече инсталиран сървър на същата машина. Удостоверяването при PostgreSQL е
оставено на подразбиращото се \code{scram-sha-256}, защото клиентът реализира SCRAM и
отслабването на сървъра би скрило кода, който наистина се изпълнява.
